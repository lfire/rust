# 第 01 讲 · 开篇：基础概念串讲

如果你从没写过 Rust，甚至不确定「编译」和「运行」有什么区别，这一讲就是为你写的。

很多教程一上来就让你写 HTTP 抓取工具，结果同时撞上语法、所有权、依赖管理、网络四堵墙。我们换个方式：**先用一讲把整张地图铺开**。每个概念只给一句直觉、一小段代码、以及「后面第几讲展开」——你不需要现在就懂，只要知道它在地图上的位置。

## 二、程序怎么跑起来

程序 = **数据 + 处理数据的指令**。你写的 `.rs` 是给人看的文本，CPU 只认识二进制。中间那一步叫**编译**：

```text
src/main.rs  ──rustc / cargo build──▶  可执行文件  ──运行──▶  屏幕输出
```

```rust
fn main() {
    println!("Hello, Rust!");
}
```

三行里已经藏了四个概念：`fn` 是函数，`main` 是入口，`{}` 是函数体，`println!` 是**宏**（带 `!`）。别急着记，[第 03 讲](/guide/hello.md) 会逐行拆。

<Compare title="解释执行 vs 编译执行" :panels='[{"label":"Python / JavaScript","code":"源码 → 解释器逐行执行\n改完立刻能跑\n类型错误往往运行时才炸","note":"反馈快，约束少"},{"label":"Rust","code":"源码 → 编译检查 → 二进制\n改完要先编译\n大量错误在编译期就被拦下","note":"前期慢，后期稳"}]' note="Rust 的「严格」本质是把调试时间提前到了写代码的时候。" />

## 三、数据怎么表示

**值**是具体的数据（`42`、`3.14`、`"hello"`）；**类型**规定这个值占多少内存、能做什么操作。同一串二进制位按 `i32` 读是 66，按 `char` 读是字母 B —— 类型就是解读方式的约定。

```rust
let x = 5;              // 把 5 绑定到名字 x
let mut y = 5;          // mut 才允许改
y = 6;
let s: &str = "hello";  // 显式标注类型
```

Rust 是**静态强类型**语言：类型在编译期确定，而且不会偷偷把字符串转成数字。[第 04 讲](/foundation/concepts.md) 讲概念，[第 09 讲](/basics/variables.md) 讲具体语法，[第 10 讲](/basics/strings.md) 专门讲字符串。

<Callout type="tip" title="默认不可变" text="`let x = 5` 之后不能再给 x 赋值，要改必须写 `let mut`。这个设计让读代码的人不用在脑子里追踪「这个值被谁改过」，后面讲并发时你会感谢它。" />

## 四、数据放在哪

内存粗略分两块：

- **栈**：大小固定、极快、函数返回时自动清空。整数、布尔值放这里。
- **堆**：大小可以运行时决定、灵活、必须有人负责释放。`String`、`Vec` 的数据在这里。

```rust
let a = 42;                        // i32，全在栈上
let s = String::from("hello");      // 字符在堆上，栈上只存「指针/长度/容量」
```

[第 05 讲](/foundation/memory.md) 会用图把这件事讲透。**为什么现在就要知道？** 因为 Rust 最核心的所有权机制，解决的就是「堆上那块内存谁负责还」。

## 五、逻辑怎么组织

```rust
fn add(a: i32, b: i32) -> i32 { a + b }   // 函数

fn main() {
    let nums = [1, 2, 3];
    let mut total = 0;
    for n in nums {                        // 循环
        if n > 1 { total += n; }          // 分支
    }
    let label = if total > 3 { "大" } else { "小" };  // if 是表达式
    println!("{} {} {}", add(1, 2), total, label);
}
```

几个要点先混个脸熟：

- **函数**把步骤打包；`impl` 里依附于某个值的函数叫**方法**；能捕获周围变量的匿名函数叫**闭包**。
- Rust 里**绝大多数东西是表达式**（有值），所以 `if` 可以直接赋给变量；函数最后一行不加分号就是返回值。
- **模式匹配** `match` 会强制你处理所有情况，后面 [第 13](/basics/match-basics.md) / [第 25 讲](/core/patterns.md) 会展开。

## 六、Rust 独有的那道坎

前面五组，别的语言也大同小异。真正让 Rust 成为 Rust 的是这一组：

> 每个值有且只有一个**所有者**；所有者离开作用域，值自动释放；想用又不想抢走所有权，就**借用**。

```rust
let a = String::from("hi");
let b = a;                 // 所有权移交给 b
// println!("{}", a);      // ❌ a 已经不能用了
```

```text
error[E0382]: borrow of moved value: `a`
```

第一次看到会懵，但它只是在编译期提醒你「这块堆内存现在归 b 管了」。没有 GC、也不用手动 `free`，靠的就是这三条规则。**L3 的 15 讲全部围绕它展开**，是全书最该放慢速度的地方。

## 七、失败与抽象

Rust 没有 `null`，也没有用异常当主力的错误处理：

```rust
// 可能没有值 → Option
let first: Option<i32> = vec![1, 2].first().copied();
// 可能失败 → Result
let text = std::fs::read_to_string("a.txt");   // Result<String, io::Error>
```

把「缺失」和「失败」写进类型，编译器就会逼你处理它们。再往上，**trait** 描述「能做什么」，**泛型**让一段代码适配多种类型 —— 这两样是 L5 所有工程架构的骨架。

<Callout type="idea" title="一条贯穿线" text="Rust 的很多设计都是同一个思路：**能放进类型里让编译器检查的，就别留到运行时靠人记**。类型、所有权、Option/Result、Send/Sync，全都是这条思路的不同侧面。" />

## 八、并发与工程

程序要同时做多件事，就会遇到「两个线程改同一块数据」的问题。Rust 用类型系统把它们分成两类：

| 路线 | 做法 | 讲次 |
| --- | --- | --- |
| 共享状态 | `Arc<Mutex<T>>`、原子类型 | [第 33 讲](/concurrency/shared-state.md) · [第 34 讲](/concurrency/atomics.md) |
| 消息传递 | channel，不共享内存 | [第 35 讲](/concurrency/channels.md) |
| 异步 | 少量线程扛大量 IO 等待 | [第 36–38 讲](/concurrency/future-executor.md) |

最后，代码要从单文件长成项目：**Cargo** 管依赖和构建，**模块**管结构，**测试**管正确性，CI/CD 管交付 —— 这就是 L5 九类工程场景要练的事。

## 九、为什么值得学 Rust

| 价值 | 含义 |
| --- | --- |
| 内存安全 | 悬空指针、重复释放、数据竞争在编译期被拦，不靠 GC |
| 零成本抽象 | 迭代器、泛型、trait 编译后和手写循环一样快 |
| 无畏并发 | 线程安全写进类型系统 |

典型场景：浏览器引擎、数据库、网络服务、CLI 工具链、WASM 前端加速、嵌入式、操作系统组件。

<Callout type="warn" title="也有不适合的场景" text="一次性数据探索脚本、快速原型、需要大量现成业务组件的后台，Python / JS / Java 通常更划算。Rust 的甜区是**长期运行、性能敏感、出错代价高**的系统。另外要清楚：编译器保证不了业务逻辑正确，那仍然需要测试。" />

## 十、学习曲线与心态

## 小结

- 八组概念：程序怎么跑、数据怎么表示、放在哪、逻辑怎么组织、所有权、失败与抽象、并发、工程。
- Rust 的独特性集中在**所有权**：没有 GC，也不用手动释放。
- 核心思路是「能交给编译期检查的，别留到运行时」。
- 六阶段递进，L3 最难但最值得慢下来；之后进入九类工程场景。
