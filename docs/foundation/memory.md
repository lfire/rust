# 第 05 讲 · 栈与堆：数据住在哪

程序运行的时候，它用到的数据都放在内存里。内存不是一整块随便用的空间，粗略分成两个用途很不一样的区域：**栈（stack）** 和 **堆（heap）**。

## 栈：像一摞盘子

想象餐厅里一摞盘子：只能从顶部放、从顶部拿，先进去的在最底下。函数调用就像往这摞盘子上放一个新盘子（叫**栈帧**）；函数返回，就把最上面那个盘子端走，它上面所有东西一起消失。

由此得到栈的三个特点：

- **快**：只需要移动一个「栈顶指针」，几乎零成本。
- **大小必须事先确定**：编译器得知道这个盘子有多大。
- **自动回收**：函数一返回，整帧自动作废，不需要谁去清理。

整数、浮点数、布尔值、字符，这些大小固定的值都适合放栈上。

## 堆：像仓库里的储物柜

如果数据的大小要到运行时才知道（比如用户输入的一段文字有多长），就没法提前给它准备一个固定大小的盘子。这时程序会向操作系统「租」一块堆空间，拿到一个**地址**，把这个地址记在栈上。

堆的特点是：

- **灵活**：大小可以运行时决定，还能增长。
- **稍慢**：要找空间、要记录、要归还。
- **必须有人负责还**：否则这块空间会一直被占着，这就是「内存泄漏」。

## 关键区别：String 为什么特殊

```rust
fn main() {
    let a = 42;                       // i32，全部在栈上
    let s = String::from("hello");    // 文字在堆上，栈上只存三个数字
    println!("{} {}", a, s);
}
```

变量 `s` 在栈上其实只占三个机器字：**指向堆的指针、长度、容量**。真正那 5 个字节 `h e l l o` 在堆上。这个「栈上的小结构 + 堆上的大数据」的组合，是理解 Rust 所有权的钥匙。

## 为什么不能简单「复制指针」？

假设 `let b = a` 只是把指针复制一份，那么 `a` 和 `b` 会指向同一块堆内存。等两个变量都离开作用域时，就会**对同一块内存释放两次**（double free），程序直接崩溃。

语言们各自的选择：

| 做法 | 代表语言 | 代价 |
| --- | --- | --- |
| 复制时把堆数据也深拷贝一份 | C++（部分情况） | 慢，且容易忘记 |
| 复制指针，用 GC 统一回收 | Java / JS / Python | 需要运行时、会有停顿 |
| 复制指针，但让旧变量立即失效 | **Rust（Move）** | 编译期检查，零运行时开销 |

## 小结

- 栈：固定大小、极快、随函数调用自动创建和销毁。
- 堆：运行时大小、灵活、需要明确谁负责释放。
- `String` 这类类型在栈上放「指针/长度/容量」，数据本体在堆上。
- Rust 用**移动**而不是复制指针，来避免同一块堆内存被释放两次。
